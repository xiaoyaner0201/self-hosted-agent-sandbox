# 0.4.0rc1 — prerelease

This integrated release candidate is available as a GitHub prerelease, not a stable
release or a PyPI upload. It does not upgrade production or change cluster policy.
The Python distribution, `__version__` and public tag use `0.4.0rc1` / `v0.4.0rc1`.
Install it explicitly; the stable baseline remains 0.3.0.

## Changes and contracts

- Recoverable `Allocation` snapshots, `on_allocation`, original exception
  `.allocation`, `ReleaseError`, `release_verified()` and `release_allocation()`.
  Persist inventory before every verified-delete attempt, including retries.
  Verification is UID-aware API resource absence, not remote process-death proof.
- Local POSIX streaming process groups are reaped on timeout, stream-writer
  exceptions and exceptional exits. Local cleanup is not remote cancellation.
- Artifact receipt validates the complete envelope and checksums, applies locally,
  then sends a separate ACK. A failed receipt stays pending; the next command must
  receive it before pushing host files, in both default and strict modes.
- Explicit `pull()` recovery and opt-in strict handling via
  `agent_sandbox_strict_pull` / `AGENT_SANDBOX_STRICT_PULL`. A strict close failure
  preserves the claim. Verified release deliberately does not pull: absence and
  artifact delivery are independent verdicts.

## Compatibility and recovery

Default best-effort `close()` / `release()` and execute's `{output, returncode}`
shape are retained. Strict mode is not enabled implicitly. File/directory type
conflicts are errors without ACK, not permission to recursively delete host
content: resolve the conflicting host entry explicitly, then call `pull()` on
that same instance. Serialize commands per instance, and join acquisition and
execution owners before verified release. Callers own durable ledgers/reapers,
heartbeats, retries, business authorization and artifact retention/validation.
Observer RBAC needed by verified cleanup is opt-in; existing cluster RBAC is unchanged.

## Verification and limits

Required local gates: routing table (94 cases), routing fuzz (seed 1, 40000
iterations), complete core script, lifecycle (31), artifact ACK (11), integrity
(10), integration cross-regressions (5). Lifecycle uses fake kubectl; Docker tar
transport and local POSIX process groups are real. Installed-wheel tests must
exercise the same lifecycle/receipt paths, not only an editable checkout.

The historical v0.3.0 Temporal canary is retained as historical evidence only.
The new APIs have **not** been live-canary tested with Kubernetes/gVisor/Temporal.
There is no new remote physical process-death, worker/node TTL-fault, cross-process
recovery, or production rollout acceptance.

A historical automatic file-to-directory conversion probe does not pass under
the fail-closed contract: callers must explicitly resolve host type conflicts.
Same-instance conflict recovery is tested separately. One initial concurrent
lifecycle stress run exceeded a small fixture deadline; unchanged isolated
reruns and the final serial source/wheel gates passed. These results are not
a claim of live-cluster acceptance or a realtime deadline SLA.

See [lifecycle](../lifecycle.md), [artifact receipt](../artifact-pull.md), and
[Temporal boundaries](../temporal.md) for full contracts.

验证、本地流式进程组收割，以及校验完整制品并落盘后再 ACK 的回执协议。
默认 best-effort 与执行结果结构兼容；strict 需显式开启。pending 未收齐时两种模式
都禁止旧宿主文件覆盖远端。类型冲突不自动删除宿主树，须调用方清除冲突后在同实例

冒充新 API 实机验收。
